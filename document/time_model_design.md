# 時間のモデルの設計案(段階3)

状態: **確定(2026-10-11)**。シミュレーターと現在地の測定まで実装済み(`puyo-core/src/timed.rs`、
結果は [versus_log.md](versus_log.md))。時間の定数は、確認の際にいただいたぷよぷよ通の目安と計算式に合わせた。

背景と経緯は [versus_plan.md](versus_plan.md) と [versus_log.md](versus_log.md)。

## 目的

今の同期ターン制では、連鎖はそのターン内で一瞬で解決し、おじゃまは次のターンに降る。
そのため、組む途中の相手を小さな連鎖で潰す戦い方が最適になり、自己対戦の学習も
その方向に進んだ(自分の最大連鎖が 約5 → 約4)。

ぷよぷよ通では、連鎖が撃ち終わるまでに時間がかかり、その間も相手は手を進められる。
この「時間」をシミュレーターに入れて、次のような駆け引きが意味を持つようにする。

- 潰し: 相手が組み終わる前に、小さな連鎖で攻撃する
- 大連鎖: 潰しを受けても耐えられる形で組み、大きく撃つ
- 返し(対応): 相手の連鎖が続いている間に、自分の連鎖を撃って相殺する・撃ち返す

## 今の同期ターン制(比較用)

1. 両者が同じツモを同時に置き、それぞれ連鎖を最後まで解決する。
2. このターン連鎖しなかったプレイヤーには、前のターンまでに届いていた予告おじゃまが最大30個降る。
3. 攻撃を授受する(自分の予告を相殺 → 残りを打ち消し合い → 差分を相手の予告へ)。
4. 窒息判定。

## 時間のモデルの進行ルール

### 時間の単位

- 時間はフレーム(1/60秒)の整数で数える。各プレイヤーは自分の状態と「次に何かが起きる時刻」を持ち、
  シミュレーターは早い方の出来事から順に処理する(イベント駆動)。
- 時間は盤面から計算する(`Timing`。すべての数値は設定で変えられる)。高速落下を使う前提の、ぷよぷよ通の目安。

| 区間 | 計算式 | 目安 |
|---|---|---|
| 設置1手 | 12(次のぷよの出現)+ 2 × 落下段数 + 20(接地)。ちぎりがあれば + ちぎり落下[段差] + 20 | 44〜52F(代表 48F = 0.8秒) |
| 連鎖1つ | 50(消去)+ 落下があれば (2 × 最大落下段数 + 20)。落下が無ければ 50 のみ | 72〜80F(代表 75F = 1.25秒) |
| おじゃま落下 | ちぎり落下[落下段数] + 接地(3個以下 8F / 18個以下 24F / それ以上 32F) | 60〜70F(代表 66F = 1.1秒) |

- ちぎり落下[段数 1〜12] = 10, 15, 19, 22, 25, 28, 31, 33, 35, 37, 39, 41(F)
- 設置の落下段数は、出現位置(12段目)から、先に着地するぷよの段までの差。ちぎりの段差は、横置きの2列の高さの差。
- 連鎖の最大落下段数は、消えた後、各列の一番上のぷよの下にある空きの数の最大。
- おじゃまの落下段数は、降る列のうち一番低い列の高さから12段目までの差。
- 打ち切りは5分(18,000F)。
- 比率は 設置 : 連鎖 : おじゃま ≒ 1 : 1.6 : 1.4。
- 値は逆アセンブル解析(Puyo Nexus)と、実機対戦用 AI フレームワーク puyoai の定数に基づく近似で、
  数フレームの誤差はありうる(厳密さは求めない)。

### プレイヤーの状態

各プレイヤーは次のどれかの状態にある。

1. **操作待ち**: 次の手を決める。AI に手を聞くのはこの状態のときだけ。
2. **設置中**: 手を決めてから `PLACE_FRAMES` 後に着地する。
3. **連鎖中**: 着地後に消えるぷよがあれば、`CHAIN_LINK_FRAMES` ごとに1つずつ連鎖を進める
   (`chain.rs` の `ChainResolver` で1連鎖ずつ解決する)。
4. **おじゃま落下中**: 降るおじゃまがあれば、`OJAMA_FALL_FRAMES` 後に落下を終える。

連鎖もおじゃまの落下も無ければ、着地した時点で操作待ちに戻る。

### ツモ

- 両者とも同じツモの列を使う(ぷよぷよ通と同じ)。
- ただし、手を進める速さが違えば、それぞれ列の別の位置にいる。各プレイヤーは自分の位置を持ち、
  自分の現在・ネクスト・ネクネクを見る。

### おじゃまの予告・相殺・落下

ぷよぷよ通に合わせて、次のようにする。

- **攻撃は連鎖1つごと**: 連鎖の1つ分を解決するたびに、その時点までの得点をおじゃまに換算する
  (端数の持ち越しと全消しボーナスは今と同じ)。
- **相殺**: 生んだおじゃまは、まず自分の予告おじゃまを減らし、残りを相手の予告に加える。
- **確定と未確定**: 相手の予告に加えたおじゃまは、自分の連鎖が終わるまでは「未確定」で、
  連鎖が終わった時点で「確定」になる。
- **落下**: 組ぷよが着地して連鎖が起きなかったとき、確定した予告おじゃまが最大30個降る。
  相手の連鎖が続いている間は、その連鎖が送ってくる分(未確定)は降らない。
  そのため、相手の連鎖中に自分の連鎖を撃てば、届いた予告を相殺できる(返し)。

今の同期ターン制にある「同時に生んだ攻撃どうしを打ち消し合う」処理は、連鎖1つごとの相殺に置き換わる。

### 勝敗

- 窒息の判定は、着地・連鎖・おじゃま落下が終わるたびに行う(左から3列目の12段目)。
- 両者が同じフレームで窒息したら引き分け。`MAX_FRAMES` に達したら打ち切り(勝敗なし)。

## 学習への影響

### 1手の意味が変わる

- 今は「1ターン = 両者が1手ずつ」。時間のモデルでは、学習側が操作待ちになるたびに1ステップとし、
  その間に相手は0手のことも、数手打つこともある(相手が連鎖中なら0手、こちらが連鎖中なら数手)。
- 学習の環境は、学習側の次の操作待ちまで時間を進め、その途中で相手が操作待ちになれば相手の手を求める。

### 観測に加える情報(案)

**対局全体の情報に追加**

- 相手が連鎖中か、相手の連鎖の残りの数と、その連鎖が送ってくるおじゃまの見込み
  (相手の盤面は見えているので、残りの連鎖は盤面から計算できる)
- 相手の連鎖が終わるまでの時間
- 自分の予告おじゃまのうち、確定分と未確定分

**手ごとの特徴量に追加**

- この手にかかる時間(設置 + 起きる連鎖の長さ)
- この手の連鎖が、相手の今の連鎖より先に終わるか
- この手の連鎖で相殺できる量(確定分・未確定分の両方)
- この手の後に降ってくるおじゃま(確定分だけ)と、降った後に窒息するか・残る潜在連鎖

- 戦い方の指標として、対戦中の最大連鎖の平均と、勝った局の最大連鎖も記録する。

## 実装の方針

1. **Rust に時間のモデルのシミュレーターを新しく作る**(`puyo-core/src/timed.rs`)。
   今の `Versus`(同期ターン制)は残す。`phase.rs` の部品(設置、連鎖の解決、おじゃまの降下)を再利用する。
2. **複数局をまとめて進める機能も Rust に入れる**。学習速度の改善で、残るボトルネックが
   環境シミュレーション(Python で1局ずつ進める部分、約46%)だったため、作り直すこの機会に入れる。
3. リプレイと動画: リプレイは「手 + その手を決めた時刻」を記録する。動画はフレーム時刻に合わせて
   両者の盤面を並べる(今の描画の拡張)。
4. 段階的に進める:
   1. シミュレーター(ルールのテストを含む)
   2. 現在地の測定: greedy と、同期ターン制の対戦の完成版を、時間のモデルで対戦させる
      (同期ターン制のときの段階0にあたる)
   3. 特徴量とネットワークの追加
   4. 学習
