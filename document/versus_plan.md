# 対戦学習の進め方

1人プレイの学習(→ [training_log.md](training_log.md))で、平均最大連鎖 約9、10連鎖率 約3割の AI ができた。
連鎖を組む能力はここで一区切りとし、対戦の学習に進んでいる。このファイルには現時点の方針をまとめる。

段階ごとの測定結果と、方針を変えた経緯は [versus_log.md](versus_log.md) に記録する。

## 決定事項

### ルールモデル: 同期ターン制から「時間のモデル」に移る

今のシミュレーターは同期ターン制。

- 両者が同じツモを同時に置き、連鎖はそのターン内で一瞬で解決する。
- このターンに連鎖しなかったプレイヤーには、前のターンまでに届いていた予告おじゃまが最大30個降る(1手の猶予)。

このルールでは「連鎖にかかる時間」がないため、組む途中の相手を小さな連鎖で潰す戦い方が最適になり、
自己対戦の学習もその方向に進んだ(自分の最大連鎖が 約5 → 約4)。大連鎖、潰し、返しの駆け引きを
学ばせるため、連鎖やツモの設置に時間がかかる「時間のモデル」を導入する(段階3)。

### 目標

- 段階2の目標「greedy と1人プレイの完成版の両方に勝率8割以上」は達成した。
- 段階3(時間のモデル)の最初の目標「greedy と同期ターン制の対戦の完成版の両方に8割以上、最大連鎖の平均が約4より
  伸びる」も達成した。
- **目標の変更(2026-10-12)**: 目指すのは「一番強い AI」ではなく、**大連鎖を組んで魅せて勝つ AI**。
  理想は、相手に大きめの連鎖を撃たせて、大連鎖で返して勝つこと。勝ち方に応じて報酬を変え(`env.reward: style`)、
  勝率に加えて「決め手の連鎖の大きさ」「8連鎖以上で決めた勝ちの割合」「返し勝ちの割合」で評価する。

## 開発の段階

### 段階0〜2(完了)

- 段階0: 1人プレイの完成版は、対戦では greedy に勝率35%。予告おじゃまに対応できていなかった。
- 段階1: 予告おじゃまを考えた手ごとの特徴量(20個)と対局全体の情報(8個)、相手の盤面を見るネットワーク。
  1人プレイの重みを引き継ぎ、追加部分は影響ゼロで始める。
- 段階2: 自己対戦(相手は greedy : 1人プレイの完成版 : 過去の自分 = 1 : 1 : 2)。
  勝ち +1 / 負け −1 と、1000万ステップで0まで弱める補助報酬。750万ステップ付近で頭打ちになり、1647万ステップで終了。

詳細は [versus_log.md](versus_log.md)。

### 学習速度の改善(完了)

相手の推論を直接まとめて行い(過去の自分は重みを束ねて1回で)、並列環境数を 16 → 64 にした。
約535 → 約1,950 steps/s(3.65倍)。残るボトルネックは環境シミュレーション(約46%)で、
時間のモデルのシミュレーターを作るときに Rust で複数局をまとめて進める形にする。詳細は [versus_log.md](versus_log.md)。

### 段階3: 時間のモデル(進行中)

設計は [time_model_design.md](time_model_design.md)(確定)。

1. シミュレーター(`TimedVersus`)と現在地の測定(完了)。時間のモデルでは、1人プレイの完成版が
   greedy に63%(同期ターン制では35%)、同期ターン制の対戦の完成版は68%(同82.6%)。
2. 時間の情報を観測と特徴量に加える(完了。手ごと22個、対局全体17個)。
3. 学習用の環境(完了。`TimedBatch` で複数局をまとめて並列に進める)。
4. 学習: `versus_timed`(500万ステップ)で最初の目標を達成した(greedy に97%、同期ターン制の対戦の完成版に86〜98%)。
   大連鎖型の相手を学習の相手に加えた `versus_timed_b` を経て、目標の変更に合わせて勝ち方の報酬の
   `versus_timed_style` に移った。
5. 「魅せて勝つ」ための学習:
   - `versus_timed_style`: 勝ち方の報酬で返し勝ちは増えたが、決め手の連鎖は約7で止まった。
   - `versus_timed_style2`(報酬の差を広げる)、`versus_timed_drill`(組む練習の対局を混ぜる)は効かなかった。
     原因は大連鎖を「組めない」こと(練習の対局でも32手で最大連鎖 約6)。
   - 3手先まで全部試す先読み探索は、同じ条件で AI よりずっと大きな種を育てた。
   - `versus_timed_look`(進行中): 先読みの結果を手ごとの特徴量(3個)として見せる。500万ステップで、組む力
     (練習の対局32手 6.1 → 7.8、10連鎖以上 1% → 20%)と勝ち方の指標(peer への返し勝ち 33% → 60%)がそろって伸びた。

詳細は [versus_log.md](versus_log.md)。

### 段階4以降(候補)

- 打つときに先読み探索を足す
- 相手の選び方を、負けやすい相手を多めに選ぶ方式(PFSP)にする

## 進め方

1. `versus_timed_look`(`configs/versus_timed_look.yaml`)は2000万ステップで終了(2026-10-16)。
   600万ステップ以降は横ばいで、「魅せる」指標だけ緩やかに伸びた。次に、候補(500万: 勝率重視、950万、
   最終版: 魅せ重視)を同じ条件で比べて、この段階の完成版を決める。
   - 比べる指標: 連鎖を組む相手(peer、solo_play、origin)への勝率・決め手の連鎖・8連鎖以上で決めた割合・返し勝ちの割合、
     練習の対局の最大連鎖、候補どうしの直接対決(各400局)。
   - greedy や sync_versus のような潰しに来る相手には、6〜7連鎖で返すのが合理的。こちらは勝率が保てていればよい。
2. 次の課題は10連鎖以上を撃ち切ること。練習の対局では10連鎖以上が約2割だが、先読みで見ると種が10連鎖以上に育つ局面は
   約4割あり、育った種を撃ち切るところに伸びしろがある。
3. 学習と並行してできる改善(候補。手を付けるときは相談する):
   - 先読みの観測の高速化(1局面 約9ms がボトルネック)
   - 評価をまとめて並列に進める(`TimedBatch` を使う。今は先読みのモデルの評価が1局ずつで遅い)
   - 時間のモデルでの総当たりの Elo(`scripts/league.py` は今は同期ターン制のみ)
4. 結果と方針の変更は [versus_log.md](versus_log.md) に追記する。
